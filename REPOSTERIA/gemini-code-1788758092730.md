\# Specification Document: Repostería PWA (Google Workspace Headless Backend)



\## 1. Visión General del Proyecto



\### 1.1 Objetivo

Desarrollar una aplicación web progresiva (PWA) instalable y multiplataforma (Android y PC) diseñada para la gestión operativa y de costos de un emprendimiento de repostería y pastelería. La plataforma permite:

\- Registrar compras de insumos y recalcular costos unitarios en tiempo real.

\- Gestionar un recetario interactivo con imágenes y procedimientos enriquecidos.

\- Descontar automáticamente el stock de insumos al registrar nuevas preparaciones.

\- Operar \*\*Offline-First\*\* y sincronizar cambios cuando se restablezca la conexión.

\- Garantizar \*\*costo cero de servidores\*\* utilizando Google Workspace (Sheets, Docs, Drive) como backend relacional y multimedia mediante autenticación de usuario (OAuth 2.0).

\## 3. Esquema de Base de Datos (Google Sheets)



El archivo maestro de Google Sheets debe contener 5 pestañas organizadas relacionalmente:



\### 3.1 Pestaña `Insumos`

| Columna | Tipo de Dato | Descripción |

| :--- | :--- | :--- |

| `id\_insumo` | String (PK) | Código único (ej. `INS-001`) |

| `nombre` | String | Nombre del insumo (ej. Harina de Trigo) |

| `unidad\_medida` | Enum | `gramos`, `mililitros`, `unidades` |

| `stock\_actual` | Float | Inventario físico disponible |

| `stock\_minimo` | Float | Umbral para alertas de reabastecimiento |

| `costo\_unidad\_promedio` | Float | Costo promedio por gramo/ml/unidad |



\### 3.2 Pestaña `Compras`

| Columna | Tipo de Dato | Descripción |

| :--- | :--- | :--- |

| `id\_compra` | String (PK) | Código de la transacción (ej. `CMP-001`) |

| `fecha` | ISO Date | Fecha y hora del registro |

| `cantidad\_comprada` | Float | Cantidad en la unidad de medida original |

| `precio\_total` | Float | Monto pagado |

| `costo\_unitario` | Float (Calculado) | `precio\_total / cantidad\_comprada` |

| `proveedor` | String | Lugar o vendedor |

| `registrado\_por` | String | Email del usuario activo |



\### 3.3 Pestaña `Recetas`

| Columna | Tipo de Dato | Descripción |

| :--- | :--- | :--- |

\## 5. Módulos Funcionales



\### 5.1 Módulo de Inventario y Compras

1\. \*\*Creación de Insumos:\*\* Formulario para registrar el nombre, unidad de medida y nivel mínimo de inventario.

2\. \*\*Entrada de Stock (Compras):\*\*

&#x20;  - Registro de compras asignadas a un insumo.

&#x20;  - Incremento automático de `stock\_actual` en la pestaña `Insumos`.

&#x20;  - Recálculo del costo promedio ponderado por unidad:

&#x20;  $$\\text{Nuevo Costo Promedio} = \\frac{(\\text{Stock Actual} \\times \\text{Costo Promedio Ant}) + \\text{Precio Total Nueva Compra}}{\\text{Stock Actual} + \\text{Cantidad Comprada}}$$

3\. \*\*Comparador de Proveedores:\*\* Tabla interactiva para visualizar históricos de precio por gramo/ml agrupados por proveedor.



\### 5.2 Módulo de Recetario y Costeo

1\. \*\*Creación de Recetas:\*\*

&#x20;  - Carga de fotografía a Google Drive.

&#x20;  - Redacción de procedimiento que genera o actualiza un Google Doc vinculado.

&#x20;  - Selección dinámica de insumos y cantidades requeridas.

2\. \*\*Cálculo de Costo de Receta:\*\*

&#x20;  $$\\text{Costo Total Receta} = \\sum (\\text{Cantidad Requerida}\_i \\times \\text{Costo Unidad Promedio}\_i)$$

3\. \*\*Visualización Interactiva:\*\* Ficha técnica con ajuste automático de cantidades e insumos al escalar el número de porciones.



\### 5.3 Módulo de Nueva Preparación (Descuento de Stock)

1\. \*\*Acción "Preparar Receta":\*\*

&#x20;  - El usuario selecciona la receta y la cantidad de porciones a elaborar.

2\. \*\*Validación de Inventario:\*\*

&#x20;  - La app valida si existe `stock\_actual` suficiente para todos los ingredientes.

&#x20;  - Si no hay suficiente, muestra una alerta detallada indicando los faltantes.

3\. \*\*Ejecución de la Preparación:\*\*

&#x20;  - Calcula el factor de proporcionalidad: $\\text{Factor} = \\frac{\\text{Porciones Producidas}}{\\text{Porciones Base}}$.

&#x20;  - Resta las cantidades consumidas del `stock\_actual` en Google Sheets.

&#x20;  - Registra el consumo en la pestaña `Produccion`.

\## 6. Especificaciones de UI/UX (Glassmorphism System)



\- \*\*Fondo General:\*\* Gradiente fluido de tonos cálidos y suaves (`#fdfbf7` a `#e6d5c3` o dark mode pastel).

\- \*\*Tarjetas y Contenedores:\*\* Paneles con `background: rgba(255, 255, 255, 0.25)`, `backdrop-filter: blur(16px)`, `border: 1px solid rgba(255, 255, 255, 0.3)` y bordes redondeados (`rounded-2xl`).

\- \*\*Estados y Alertas:\*\*

&#x20; - Stock Crítico: Badges translúcidos en rojo/naranja (`bg-red-500/20 text-red-700`).

&#x20; - Botones de Acción: Gradientes interactivos con sombras difusas.

\- \*\*Navegación:\*\* Tab bar inferior flotante optimizado para pulgares en móviles y barra lateral colapsable en escritorio.

\## 7. Arquitectura Offline-First y Sincronización



1\. \*\*Service Worker (PWA):\*\* Intercepta peticiones de red y sirve la app desde el cache del navegador.

2\. \*\*Base de Datos Local (IndexedDB via Dexie.js):\*\*

&#x20;  - Mantiene una copia local de la base de datos de Google Sheets para lectura inmediata.

&#x20;  - Almacena en una cola de mutaciones (`sync\_queue`) cualquier acción realizada sin conexión.

3\. \*\*Mecanismo de Sincronización:\*\*

&#x20;  - Al detectar el evento `online`, la app procesa `sync\_queue` secuencialmente hacia las APIs de Google.

&#x20;  - Actualiza la copia local de IndexedDB con las respuestas confirmadas por las APIs.
